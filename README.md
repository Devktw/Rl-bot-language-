# ฟุตบอล 2v2: จะเกิด "ภาษา" ขึ้นเองไหม

ฟุตบอล 2v2 บน grid 2 มิติ (10×6) ผู้เล่นมองเห็นได้จำกัด (รัศมี 2 ช่อง) และส่ง token จากคำศัพท์ 8 ตัวหาเพื่อนร่วมทีมได้ทุก step
มีผู้รักษาประตู (ควบคุมโดย env) ยืนครึ่งบนหรือล่างของประตูและสลับฝั่งแบบสุ่ม ยิงไปฝั่งที่เขายืนโอกาสเข้าเหลือ 10%
**คนเลี้ยงบอลก้มหน้า** มองไม่เห็นผู้รักษาประตูจนกว่าจะชิดประตู ส่วนเพื่อนที่ไม่ได้ถือบอลเห็นเมื่ออยู่ครึ่งสนามฝั่งบุก
เทรนด้วย PPO โดยไม่มี gradient ผ่านช่องสื่อสาร ภาษาจึงต้องเกิดจาก reward เพียงอย่างเดียว
คำถามหลักคือ ถ้าคู่แข่ง **ดักฟังได้** จะเกิดรหัสลับหรือไม่

## โครงสร้าง
| ไฟล์ | หน้าที่ |
|---|---|
| `football/env.py` | env แบบ vectorized ใช้ team frame (ทุกทีมบุกไปทางขวา), action: เดิน 4 ทิศ/อยู่นิ่ง/ส่ง/ยิง + token |
| `football/agent.py` | actor ร่วมในทีม + centralized critic |
| `football/scripted.py` | บอทเขียนกฎ เห็นทั้งสนาม ใช้เป็นคู่ซ้อมที่นิ่ง |
| `train.py` | PPO; `--cond` เลือกเงื่อนไข, `--opponent scripted` ให้ซ้อมกับบอท |
| `analyze.py` | MI signaling/listening, intervention (สลับ token เป็นค่าสุ่ม), lexicon heatmap, drift |

เงื่อนไข (`--cond`): `nocomm`, `asym` (แดงคุยได้ น้ำเงินใบ้), `private`, `eavesdrop` (ทุกคนได้ยินทุกคน), `spy` (น้ำเงินแอบฟังแดง)

```bash
pip install -r requirements.txt
python -m pytest -q tests
python train.py --cond asym --opponent scripted --tag _lowent --updates 400   # ~10 นาที / CPU 1 คอร์
python train.py --cond eavesdrop --updates 800                                # self-play ~35 นาที
python analyze.py runs/asym_vs_bot_lowent_s0   # ผลอยู่ที่ results/asym_vs_bot_lowent_s0/ (summary.json, lexicon*.png)
```

## ผลหลัก (env v3)

### 1. ภาษาเกิดขึ้นจริง: คำเรียก "ผู้รักษาประตูอยู่บน/ล่าง"
แดง (เทรน) vs บอท scripted, 6.5–9.8M steps

| run | win แดง | ยิงถูกฝั่ง (คนยิงมองไม่เห็น) | MI(token; ฝั่งผู้รักษาประตู) เมื่อผู้พูดเห็น | สลับ token เป็นค่าสุ่ม → ยิงถูกฝั่ง / win |
|---|---|---|---|---|
| nocomm | 0.770 | 0.464 | – | – |
| oracle (เห็นทั้งสนาม) | 0.869 | (เห็นเอง 0.992) | – | – |
| asym, ent_msg 0.01 | 0.767 | 0.486 | 0.08 | 0.469 / 0.765 |
| **asym, ent_msg 0.001, seed 0** | **0.805** | **0.648** | **0.73 bit** | **0.471 / 0.757** |
| **seed 1** | **0.816** | **0.697** | **0.90 bit** | **0.480 / 0.757** |
| **seed 2** | **0.803** | **0.641** | **0.69 bit** | **0.471 / 0.777** |

- ทั้ง 3 seed เกิดคำคู่หนึ่งที่แปลว่า "ผู้รักษาประตูอยู่บน" กับ "อยู่ล่าง" แต่**แต่ละ seed ใช้ token คนละตัว**
  (seed 0: 2/7, seed 1: 1/2, seed 2: 3/0) แสดงว่าคำเป็นสัญลักษณ์ที่ตั้งขึ้นเองตามอำเภอใจ
- **การทดสอบเชิงเหตุผล:** สลับ token เป็นค่าสุ่ม อัตรายิงถูกฝั่งตกกลับไปเท่ากับเดาสุ่ม (~47%)
  แสดงว่าผู้ยิงฟังคำนั้นและเปลี่ยนการตัดสินใจจริง
- entropy bonus ของ message ต้องต่ำ (0.001) ถ้าใช้ 0.01 แรงผลักให้ token สุ่มจะชนะแรงจูงใจให้สื่อความหมาย
- ภาษาปิดช่องว่างกับ oracle ได้ประมาณครึ่งหนึ่ง (0.77 → 0.81 จากเพดาน 0.87)

ภาพ: `results/asym_vs_bot_lowent_s*/lexicon_keeper.png`

### 2. Self-play สองทีม: ส่วนตัว vs ดักฟังได้ (seed 0, 13M steps)
| | private | eavesdrop |
|---|---|---|
| win แดง / น้ำเงิน | 0.546 / 0.440 | 0.533 / 0.446 |
| MI คำผู้รักษาประตู แดง / น้ำเงิน | 0.90 / 0.70 | 0.75 / 0.59 |
| แดงยิงถูกฝั่ง (มองไม่เห็น) | 0.720 | 0.698 |
| สลับ token ในทีมแดง → win แดง | 0.464 (−8 จุด) | 0.494 (−4 จุด) |
| **คู่แข่งได้ยินค่าสุ่มแทนคำของแดง → win น้ำเงิน** | – | **0.417 (−3 จุด)** |
| **คู่แข่งได้ยินค่าสุ่มแทนคำของน้ำเงิน → win แดง** | – | **0.509 (−2.4 จุด)** |

- ทั้งสองทีมสร้างภาษาของตัวเองขึ้นมา (คนละ token กัน)
- ในโหมดดักฟัง **ทั้งสองทีมได้ประโยชน์จากการฟังคำของอีกฝ่ายจริง** (ถ้าตัดข้อมูลที่แอบฟัง win ตก 2–3 จุด
  ซึ่งมากกว่า standard error ราว 0.5 จุด)
- ข้อสังเกตเบื้องต้น (seed เดียว ยังสรุปไม่ได้): ภายใต้การดักฟัง คำมีความชัดน้อยลง (MI ลดลง)
  และทีมแดงใช้ "คำพ้อง" สองคำ (token 1 กับ 6) สำหรับ "อยู่ล่าง"

### ขั้นต่อไป
- รัน eavesdrop/private หลาย seed เพื่อยืนยันว่า MI ลดลงจริงหรือไม่
- ให้ทีมรับ **คุมผู้รักษาประตูเองได้** การดักฟังจะมีค่ามากขึ้น (ได้ยินว่าอีกฝ่ายจะยิงฝั่งไหนก็ย้ายผู้รักษาประตูไปดัก)
  จึงน่าจะเกิดแรงกดดันให้เข้ารหัสหรือเงียบ
- ดู drift ของคำข้าม checkpoint ในโหมดดักฟัง (`summary.json` → `drift`)

## ประวัติ: รอบที่ยังไม่เกิดภาษา
- **v1** (ไม่มีผู้รักษาประตู, `results/v1/`): ไม่เกิดภาษา เพราะทีมที่เห็นทั้งสนามก็ไม่ได้เก่งกว่า
  (ไม่มี oracle gap) agent ชนะได้ด้วยการเลี้ยงบอลเดี่ยว
- **v2** (มีผู้รักษาประตูแต่ต้องเข้าใกล้ถึงจะเห็น, `results/v2/`): oracle ยิงถูกฝั่ง 80–85% แต่ทีมปกติ
  ไม่เคยเข้าใกล้ประตูพอจะเห็น (0 ครั้ง) จึงไม่มีใครมีข้อมูลให้พูดถึง
- **บทเรียน:** ต้องมี (1) oracle gap และ (2) ข้อมูลกับการตัดสินใจต้องอยู่คนละคนในสถานการณ์ที่เกิดขึ้นบ่อย
